## 1. Executive Summary & Purpose

The **AI Staff Operations Intelligence Platform** is a full-stack, enterprise-grade institutional management system engineered to orchestrate faculty operations, course schedules, task lifecycles, and academic workloads.

### Core Institutional Philosophy & Non-Surveillance Policy
- **Operational Intelligence, Not Physical Surveillance**: This platform coordinates schedules, academic activities, administrative tasks, and departmental workloads. It **DOES NOT** perform physical location tracking, biometric surveillance, or GPS monitoring.
- **Server-Clock Authoritative**: All class schedules, expected class resolutions, and activity durations are determined exclusively by authoritative server time, never vulnerable client clocks.
- **Objective Wording**: When scheduled classes lack a recorded teaching activity, the platform records:  
  `"Scheduled class activity has not been recorded."`  
  It explicitly avoids claiming staff absenteeism or speculating on physical whereabouts.
- **Tripartite Classification of System Information**:
  1. **DATABASE FACT**: Verified, immutable record directly retrieved from PostgreSQL via Prisma ORM (e.g., recorded attendance, assigned task status).
  2. **RULE-BASED CONDITION**: Deterministic evaluation against configured institutional thresholds (e.g., task due in < 24 hours, timetable slot passed grace period).
  3. **AI INSIGHT**: High-level, evidence-backed operational synthesis generated by Gemini AI with strict citations to authorized database facts.

## 3. Key Modules & Business Workflows

### A. Authentication & Session Security
- **Credentials**: Email or Staff ID identifier with bcrypt password hashing (cost factor 10).
- **Session Tokens**: Cryptographically random 32-byte tokens stored in the database **strictly as SHA-256 hashes**.
- **Transport**: Stored exclusively in `HttpOnly`, `SameSite=Lax`, `Secure` (production) cookies. Never exposed to `localStorage` or JavaScript context.
- **Password Reset**: Single-use cryptographic reset tokens hashed with SHA-256; automatically terminates all active sessions upon password reset.
- **Rate Limiting**: In-memory IP/identifier sliding-window rate limiters across auth and AI endpoints.

### B. Role-Based Access Control (RBAC) & IDOR Protection
- **ADMIN**: Complete organizational oversight across all departments, faculty profiles, master timetables, leaves, settings, and audit logs.
- **STAFF**: Restricted strictly to their own authorized profile, assigned timetable, personal attendance, assigned tasks, leave submissions, notifications, and personal reports.
- **Zero-Trust IDOR Checks**: Enforced at the route controller and service layers across URL parameters (`:id`), query parameters (`staffId`), and request bodies (`staff_id`).

### C. Timetable, Expected Class & Activity Engine
- **Timetable Management**: Conflict detection preventing overlapping time slots for the same faculty or class section.
- **Expected Class Resolution**: Authoritative resolution of current day-of-week and server-time against active academic year schedules.
- **Faculty Activity Registration**: Real-time work status tracking (`TEACHING`, `MEETING`, `PREPARING_CLASS`, `ADMINISTRATIVE_WORK`, `AVAILABLE`, `BREAK`, `LEAVE`).
- **Class Coverage Engine**: Compares timetable schedule with recorded activities to calculate institutional and department-level coverage percentages.

### D. Attendance & Leave Operations
- **Attendance Uniqueness**: Composite unique constraint (`staff_id`, `attendance_date`) prevents duplicate daily registrations.
- **Leave Integrity**: Atomic transactions approve or reject leave requests with automatic notification dispatch; enforces mutual exclusion against `PRESENT` status on approved leave dates.

### E. Task Lifecycle & Automated Monitoring
- **Lifecycle**: `PENDING` ➔ `IN_PROGRESS` ➔ `COMPLETED` (or `OVERDUE` via scheduler).
- **Task Updates**: Audited change logs with user remarks and status histories.
- **Automated Escalation**: Identifies high-priority tasks approaching due dates (< 24h) and alerts assignees.

### F. Workload Analytics & Multi-Metric Performance
- **Workload Formula**: Synthesizes weekly teaching hours, class preparation load, active task weights, and administrative duties into categorical states (`OPTIMAL`, `OVERLOADED`, `UNDERUTILIZED`).
- **Balanced Performance Weights (Default 100-Point Model)**:
  - **Attendance**: 20%
  - **Task Completion**: 25%
  - **On-Time Task Delivery**: 20%
  - **Class Coverage & Completion**: 25%
  - **Operational Activity**: 10%
- **Configurable Thresholds**: Administrable via System Settings without hardcoded calculations.

### G. Background Scheduled Jobs (7 Automated Engines)
1. `CLASS_MONITORING`: Evaluates ongoing classes past grace period (default 15m) and issues notifications.
2. `TASK_MAINTENANCE`: Transitions overdue tasks and updates status flags.
3. `TASK_RISK_ANALYSIS`: Flags high-risk tasks with impending deadlines.
4. `ATTENDANCE_ANALYSIS`: Aggregates faculty attendance compliance.
5. `TIMETABLE_CONFLICT_ANALYSIS`: Verifies room and faculty schedule consistency.
6. `WORKLOAD_ANALYSIS`: Recalculates department workload distributions.
7. `NOTIFICATION_MAINTENANCE`: Prunes stale read notifications (> 90 days).

## 4. Gemini AI Copilot & Evidence Grounding

### Security & Prompt Injection Defenses
- **Server-Side Exclusivity**: Frontend never touches `GEMINI_API_KEY`.
- **Restricted Tool Allowlist**: Exactly 17 pre-approved inspection tools (`get_staff`, `get_staff_attendance`, `get_staff_tasks`, `get_current_activities`, `get_timetable`, `get_leave_requests`, `get_workload_metrics`, `get_department_statistics`, `get_notifications`, `get_performance`, `get_audit_records`, `get_class_coverage`, `get_operational_alerts`, `get_task_statistics`, `get_attendance_statistics`, `get_department_workload`, `get_department_performance`).
- **No Unrestricted SQL**: The model has zero access to raw SQL execution, schema alteration, or data deletion primitives.
- **Strict Evidence Grounding**: The AI model answers questions based **exclusively** on retrieved database facts.
- **Deterministic Synthesis Fallback**: If Gemini API quota is exhausted (HTTP 429) or offline, the platform seamlessly generates deterministic, evidence-grounded reports without disrupting operations.

## 6. Local Setup & Production Deployment

### Prerequisites
- Node.js >= 20.x
- npm >= 10.x
- PostgreSQL >= 14.x

### Environment Configuration
Copy `.env.example` to `.env` and configure:

```bash
cp .env.example .env
```

```env
# Database Connection (PostgreSQL)
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/staff_ops_db?schema=public"

# AI Integration
GEMINI_API_KEY="your-google-ai-studio-api-key"

# Session Security (Minimum 32 characters in production)
SESSION_SECRET="your-ultra-secure-random-secret-key-32-chars-min"

# Application Settings
APP_URL="http://localhost:3000"
NODE_ENV="production"
PORT=5000
```

### Installation & Database Initialization

```bash
# 1. Install all dependencies
npm install

# 2. Generate Prisma Client
npm run db:generate

# 3. Apply database migrations
npm run db:push

# 4. Seed deterministic initial data
npm run db:seed
```

### Running in Development

```bash
# Start backend API (Port 5000)
npm run dev:backend

# Start frontend application (Port 3000)
npm run dev:frontend
```

### Production Build & Launch

```bash
# Validate TypeScript across both frontend and backend
npm run lint

# Build backend and frontend bundles
npm run build

# Start production server
npm run dev
```

## 8. Backup & Safe Rollback Procedures

### Safe Database Backup
To take a zero-downtime logical backup of the PostgreSQL database:
```bash
pg_dump --format=custom --no-owner --no-privileges "$DATABASE_URL" > "backup_staff_ops_$(date +%Y%m%d_%H%M%S).dump"
```

### Safe Database Restore
To restore into a clean staging or recovery database:
```bash
pg_restore --clean --if-exists --no-owner --no-privileges -d "$RECOVERY_DATABASE_URL" "backup_staff_ops_xxx.dump"
```

### Safe Application Rollback
1. Keep the previous build artifact directory (`dist/`) intact before swapping builds.
2. In case of deployment anomalies, redirect the reverse proxy traffic back to the prior release artifact.
3. Database migrations adhere to additive-only schemas (new nullable columns and tables) to ensure forward and backward compatibility.
